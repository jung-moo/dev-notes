# 프로세스

## 핵심

프로세스(Process)는 **실행 중인 프로그램**이다.

디스크에 저장되어 있는 프로그램을 실행하면 운영체제가 프로그램을 메모리에 올리고 실행에 필요한 자원을 할당한다.

프로세스에 할당되는 메모리의 구조는 [[process-memory]]에서 다룬다.

이렇게 실행되고 있는 프로그램을 프로세스라고 한다.

```
프로그램
  ↓ 실행
프로세스
```

같은 프로그램을 여러 번 실행하면 각각 별도의 프로세스가 만들어질 수 있다.

## 프로그램과 프로세스

프로그램은 실행할 수 있는 코드가 저장되어 있는 파일이다.

프로세스는 그 프로그램이 실제로 실행되고 있는 상태이다.

```
프로그램
- 디스크에 저장
- 실행 전 상태

프로세스
- 실행 중인 프로그램
- 운영체제로부터 메모리 등의 자원을 할당받음
```

## PID

PID(Process ID)는 **운영체제가 각각의 프로세스를 식별하기 위해 부여하는 번호**이다.

동일한 프로그램을 여러 번 실행하더라도 각각의 프로세스는 서로 다른 PID를 가진다.

```
프로세스 A → PID 1001
프로세스 B → PID 1002
```

운영체제는 PID를 이용하여 각각의 프로세스를 식별하고 관리한다.

## PPID

PPID(Parent Process ID)는 **현재 프로세스를 생성한 부모 프로세스의 PID**이다.

프로세스가 다른 프로세스를 생성하면 부모-자식 관계가 만들어질 수 있다.

예를 들어 실행 스크립트가 Java 프로세스를 실행했다면 다음과 같은 관계가 만들어질 수 있다.

```
실행 스크립트
PID 1001
    │
    └── Java 프로세스
        PID 1002
        PPID 1001
```

Java 프로세스의 PPID가 `1001`이므로 PID가 `1001`인 실행 스크립트가 부모 프로세스라는 것을 알 수 있다.

## Linux에서 프로세스 확인

Linux에서는 `ps` 명령어를 이용하여 실행 중인 프로세스를 확인할 수 있다.

```
ps -ef
```

특정 프로세스를 찾고 싶다면 `grep`과 함께 사용할 수 있다.

```
ps -ef | grep <검색할_키워드>
```

`<검색할_키워드>`에는 찾고 싶은 프로세스를 식별할 수 있는 문자열을 입력한다.

예를 들어 Java 프로세스를 찾는다면 다음과 같이 사용할 수 있다.

```
ps -ef | grep java
```

출력 결과는 다음과 같은 형태로 확인할 수 있다.

```
USER     PID    PPID  C  STIME  TTY  TIME      CMD
user     1002   1001  2  20:57  ?    00:01:30  /path/to/java ...
```

주요 항목은 다음과 같다.

- `USER` : 프로세스를 실행한 사용자
    
- `PID` : 프로세스 ID
    
- `PPID` : 부모 프로세스 ID
    
- `C` : CPU 사용 관련 값
    
- `STIME` : 프로세스 시작 시각
    
- `TTY` : 연결된 터미널
    
- `TIME` : 프로세스가 사용한 누적 CPU 시간
    
- `CMD` : 프로세스를 실행한 명령어와 인자
    

프로세스가 실제로 어떤 프로그램인지 확인할 때는 **PID뿐만 아니라 CMD도 함께 확인하는 것이 중요하다.**

프로세스 조회와 종료에 사용하는 명령어의 자세한 사용법은 [[process-command]]를 참고한다.
