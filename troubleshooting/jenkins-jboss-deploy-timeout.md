# Jenkins 배포 중 JBoss 프로세스 종료 실패로 인한 Timeout

## 핵심

Jenkins를 통한 배포 과정에서 **SSH Timeout이 발생하며 배포가 정상적으로 완료되지 않는 문제**가 발생했다.

Jenkins 로그와 서버의 프로세스 상태를 확인한 결과, 기존 [[jboss-process|JBoss 프로세스]]가 정상적으로 종료되지 않고 남아 있는 것을 확인했다.

잔존 프로세스를 직접 종료한 뒤 Jenkins 배포를 다시 실행하여 정상적으로 배포되는 것을 확인했다.

```
Jenkins 배포
    ↓
JBoss 종료 및 재기동
    ↓
SSH Timeout 발생
    ↓
Jenkins 로그 확인
    ↓
JBoss 프로세스 상태 확인
    ↓
기존 JBoss 프로세스가 남아 있는 것을 확인
    ↓
잔존 프로세스 종료
    ↓
Jenkins 배포 재실행
    ↓
정상 배포 확인
```

## 문제 상황

Jenkins를 통해 애플리케이션을 배포하는 과정에서 다음과 같은 Timeout이 발생했다.

```
Exec timed out or was interrupted after 120,000 ms
```

Jenkins는 SSH를 통해 배포 대상 서버에 접근하여 WAR 파일을 전달하고 JBoss를 재기동하는 작업을 수행하고 있었다.

배포 과정에서 약 120초 후 Timeout이 발생하면서 정상적으로 배포가 완료되지 않았다.

## 문제 확인

먼저 Jenkins 로그를 확인하여 어느 과정에서 문제가 발생했는지 확인했다.

로그를 통해 단순히 WAR 파일 전송에 실패한 것이 아니라 **JBoss 재기동 과정에서 작업이 지연되고 있을 가능성**을 확인했다.

이후 서버에서 현재 실행 중인 JBoss 프로세스를 확인했다.

```
ps -ef | grep <JBoss_프로세스_키워드>
```

프로세스를 확인한 결과, 종료되어야 할 기존 JBoss 프로세스가 여전히 남아 있는 것을 확인했다.

## 조치

정상적으로 종료되지 않고 남아 있는 JBoss 프로세스의 PID를 확인했다.

```
ps -ef | grep <JBoss_프로세스_키워드>
```

확인한 프로세스를 종료했다.

```
kill -9 <PID>
```


프로세스가 정상적으로 종료되었는지 다시 확인했다.

```
ps -ef | grep <JBoss_프로세스_키워드>
```

이후 Jenkins에서 배포 작업을 다시 실행했다.

## 결과

잔존 JBoss 프로세스를 종료한 후 Jenkins 배포를 다시 실행하자 **JBoss가 정상적으로 기동되었고 배포도 성공적으로 완료되었다.**

따라서 이번 배포 실패는 Jenkins 자체의 단순한 파일 전송 실패가 아니라 **기존 JBoss 프로세스가 정상적으로 종료되지 않은 상태와 관련된 문제**임을 확인할 수 있었다.

다만 **JBoss 프로세스가 최초에 정상 종료되지 않은 근본적인 원인까지는 확인하지 못했다.**

따라서 이번 조치는 문제 상황에서 서비스를 정상화한 것이며, JBoss가 정상 종료되지 않은 근본 원인을 제거한 것은 아니다.

## 트러블슈팅에서 배운 점

### Timeout 메시지만 보고 원인을 판단하면 안 된다

Jenkins에서는 SSH Timeout으로 나타났지만 실제로 확인해야 할 대상은 SSH 자체만이 아니었다.

```
Jenkins Timeout
      ↓
SSH 문제?
      ↓
배포 스크립트 문제?
      ↓
JBoss 종료 문제?
      ↓
JBoss 프로세스 상태 확인
```

Timeout은 **결과로 나타난 현상**이고 실제 원인은 다른 단계에 존재할 수 있기 때문에 로그를 통해 작업이 어느 단계까지 진행되었는지 확인해야 한다.

### 프로세스 상태 확인이 중요하다

서버 애플리케이션의 종료 및 재기동 문제가 발생하면 현재 프로세스 상태를 확인하는 것이 중요하다.

```
ps -ef | grep <프로세스_키워드>
```

이를 통해 다음과 같은 내용을 확인할 수 있다.

- 프로세스가 실제로 실행 중인지
    
- 종료되어야 할 기존 프로세스가 남아 있는지
    
- 대상 프로세스의 PID가 무엇인지
    

프로세스와 PID에 대한 자세한 내용은 [[process|프로세스]]와 [[linux/process-command|Linux 프로세스 명령어]]에서 다룬다.

### 장애 복구와 근본 원인 해결은 구분해야 한다

이번 문제에서는 잔존 JBoss 프로세스를 종료하여 정상적으로 배포할 수 있었다.

하지만 이것만으로 **JBoss 프로세스가 왜 정상적으로 종료되지 않았는지**까지 설명할 수 있는 것은 아니다.

```
장애 복구
기존 JBoss 프로세스 종료
→ Jenkins 재배포 성공

근본 원인 분석
JBoss가 왜 정상 종료되지 않았는가?
→ 추가 분석 필요
```

따라서 트러블슈팅을 기록할 때는 **확인한 사실과 아직 확인하지 못한 원인을 구분해서 기록해야 한다.**

## 추가로 확인할 내용

동일한 문제가 다시 발생한다면 다음 단계로 JBoss가 정상적으로 종료되지 않은 원인을 추가로 확인한다.

- JBoss 종료 시점의 서버 로그
    
- 종료 스크립트의 실행 결과
    
- 종료 과정에서 장시간 수행되는 작업
    
- 프로세스가 종료되지 못하도록 하는 Thread 존재 여부
    
- Jenkins가 실행하는 재기동 스크립트의 동작
    
- Jenkins SSH Timeout 설정과 실제 재기동 소요 시간
    

이를 통해 단순히 잔존 프로세스를 종료하는 것에서 끝나지 않고 **JBoss가 정상 종료되지 않는 근본 원인과 재발 방지 방법까지 확인하는 것**을 목표로 한다.
